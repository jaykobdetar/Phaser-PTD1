# Persistence and local launcher audit

Scope: the PTD 1 game, its local PokéCenter, browser profile storage, JSON imports/backups, and the Python launcher/server. All probes used generated fixtures and temporary storage. No player saves were read, changed, or deleted. PTD 2/3 and hypothetical public hosting were excluded.

Six concrete issues were reproduced, proposed, approved, and fixed. File references below are relative to `outputs/phaser-port`; line references identify the resulting implementation.

| Finding | Evidence before the change | Fix and current location |
| --- | --- | --- |
| Two launcher processes could both accept the same disk revision. | Running the real `GameHandler` in two independent processes sharing one temporary save folder returned HTTP-equivalent 200/revision 1 twice. The final bank contained only the second update. `threading.Lock` coordinates one process, while the launcher supports separate `--port` values with the same save folder. Baseline: `work/audit-server-multiprocess.json`. | `local_server.py:38` now holds a save-folder OS advisory lock around each read/CAS/write in addition to the existing thread lock. POSIX uses `fcntl.flock`; Windows uses `msvcrt.locking`. The lock is released by the OS on process exit, and its file is retained. Existing JSON format, revision semantics, temporary-file replacement, previous-file backup, loopback binding, and origin checks remain. |
| Browser mirror quota failure blocked an otherwise healthy disk save. | The actual extracted `App.store` method received a synthetic quota error only for the compatibility profile key. It returned false and made zero disk PUTs. | `src/main.js:251` makes that compatibility mirror best effort, records `cacheError`, and continues to the authoritative bank save. The existing mirror stays intact. Both disk and browser bank failures still report failure through the existing pipeline. |
| Full-cache disk loading worked, but the Center immediately failed during refresh. | `LocalProfiles.initialize()` accepted a valid disk bank while retaining displaced browser records; `CenterService.refresh()` then threw from an unguarded backup attempt. The Center entry point invokes this sequence. | `src/local-services.js:170` permits authoritative refresh when the displaced draft is already preserved in the browser record. An in-memory-only draft still blocks refresh if it cannot be backed up. Failed backup payloads are retained and must be copied before later cache publication can overwrite their original records (`backup`/`publish`). |
| Empty-profile refresh repeatedly copied the same compatibility mirror. | After an empty-bank import, five refreshes created five identical backup records. `publish()` intentionally retained the old compatibility mirror for the empty active slot. | `src/local-services.js:66` skips mirror backup when no replacement profile exists. The existing mirror remains untouched across refreshes and reopening. No old backups are removed. |
| Delayed storage events could falsely mark an accepted bank stale. | After accepting bank revision/content B, delivery of an older event for A produced `PROFILE_CONFLICT`, even though actual storage still exactly matched the accepted baseline B. | `src/local-services.js:28` compares the current browser record to the accepted baseline, as the write CAS already does. Older event payloads cannot invalidate already accepted state; genuinely newer records still trigger conflict hooks. |
| Every legacy game save normalized the full bank twice. | Twelve saves of a supported 5,000-Pokémon collection invoked whole-bank validation 24 times. The synthetic baseline median synchronous save duration was 15.63 ms. | `src/local-services.js:218` restores required Center state into the candidate before one validation, which creates the isolated queued snapshot. Twelve saves now invoke 12 validations. The initial post-change median was 14.30 ms. Timing is illustrative and machine-dependent; the removal of the duplicate normalization is exact. Immediate validation errors, ownership rules, and queued snapshot isolation remain covered. |

## Verification

- `tests/local-store.test.js`, `tests/local-transactions.test.js`, `tests/original-center-gifts.test.js`, and `tests/original-save.test.js`: **39 tests passed** after final review. New cases cover empty-slot refresh/reopen, full-cache initialization plus refresh, preservation of an in-memory-only draft, deferred backup completion before cache replacement, stale storage event delivery, single validation, queued snapshot isolation, and malformed retained Center rejection.
- `tests/local-server-process.test.py`: **2 tests passed**. The first runs actual disk handlers in independent processes, holds one inside the critical section, verifies the other cannot enter, and expects one accepted revision and one conflict. The second terminates the lock holder and verifies the next process can save without deleting the lock file.
- `local_server.py` passed Python compilation.
- `work/audit-persistence-repro.mjs --fixed` reproduces the corrected outcomes; its post-change output is `work/audit-persistence-fixed.json`. Original measurements remain in `work/audit-persistence-repro.json`.
- `work/browser-game-import-sync.mjs` now includes the actual browser `App.store` compatibility-mirror quota case. It still covers delayed/rejected imports, successful retry, stale navigation, conflict UI, and exactly one save before Center navigation. Root reran the browser workflow successfully, including the mirror-quota save case.
- Root reran `tests/local-server.test.py` successfully: the HTTP protocol, revision, backup and origin checks pass.
- The POSIX lock branch was exercised. The Windows branch is standard-library-only but could not be executed in this Linux environment.

Final semantic review found that `App.store` could still bypass deferred backup protection by directly replacing a large displaced compatibility mirror with a smaller current profile. The corrected path uses `LocalProfiles.stageProfileDraft()` before the normal queued save. Both synchronous draft staging and committed publication flush deferred backups first. This retains the existing last-second draft safeguard while ensuring a blocked backup cannot be bypassed. The no-manager path retains direct single-save persistence.

`tests/local-store.test.js` executes the actual `App.store` method against a byte-counted storage adapter containing a 100-Pokémon displaced draft. Disk saving succeeds while the entire old mirror remains durable; after quota is lifted, the exact old bank and mirror are backed up before replacement. It also verifies ordinary browser/disk saves, a held disk acknowledgment, and the single-save fallback. The independent reviewer reran the original byte-cap reproducer and confirmed the old mirror now remains durable after saving.

Deferred retention is limited to displaced browser-bank and compatibility-mirror records. A failed backup of an uncommitted autosave is not appended to this queue: its current draft remains in the live bank as before. Thirty repeated full-cache/offline autosaves leave the two original deferred records unchanged, avoiding a growing list of whole-bank snapshots.

## Boundaries checked

The launcher still serves only the built `dist` tree and binds loopback; default saves remain outside the served directory. The API retains its size limit, JSON/type checks, finite-number serialization, same-origin checks, and atomic file replacement. Browser transactions retain isolated synchronous mutation, explicit conflict recovery, storage locking, and exact disk revision comparison. This audit did not add online authentication, alter gameplay, delete backups, or modify imported/player data.
